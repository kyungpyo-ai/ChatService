# 콘텐츠 안전 대응 절차

> ⚠️ 이 문서는 법률 자문이 아니다. 아동·청소년의 성보호에 관한 법률상 온라인서비스제공자의
> 신고 의무 등 실제 법적 요건은 변호사 검토 후 확정한다(§ROADMAP Phase 7.7 상단 면책 고지
> 참고). 지금은 "무엇을 정리해야 하는지" 목차와 현재 시스템으로 즉시 실행 가능한 조치만
> 채워둔 상태다 — (2), (3)의 세부 연락처·양식은 법률 검토 이후 확정한다.

## 1. 아동성착취물(CSAM) 발견 시 대응 절차

1. **즉시 차단** — `/admin`의 기존 강제 삭제 기능(`admin_force_delete_room`,
   `admin_force_end_random_session`)으로 해당 메시지가 포함된 방/랜덤채팅 세션을 즉시
   종료·삭제한다. 이 조치는 관리자 감사 로그(`admin_audit_logs`)에 자동 기록된다.
2. **원본 격리(완전 삭제 금지)** — 수사 협조 목적상 원본 파일을 즉시 파기하지 않는다.
   Storage에서 일반 접근이 불가능한 별도 경로로 이동하거나 접근 권한만 차단한다.
   **(세부 이동 경로·보관 기간은 법률 검토 후 확정 — 미확정)**
3. **관계기관 신고** — 방송통신심의위원회, 경찰청 사이버수사대 등 관계기관에 신고한다.
   **(신고 채널·양식·담당 연락처는 법률 검토 후 확정 — 미확정)**

## 2. 미성년자 대상 성범죄 정황 신고 처리 원칙

새 테이블/컬럼을 추가하지 않고, 기존 `/admin/reports` 처리 순서 안에서 우선순위만 정책으로
둔다 — 신고 큐는 이미 최신순 정렬이라 실시간에 가깝게 노출되므로, 이 규모의 트래픽에서
별도 우선순위 필드를 추가하는 것은 과설계로 판단했다(§DEVELOPMENT_PLAN 7.7.3).

- 신고 사유(`reports.reason`)나 상세 내용(`reports.detail`)에 미성년자 관련 정황(예:
  "미성년자임을 밝힌 대화 중 성적인 대화로 유도")이 담긴 신고는 관리자가 큐의 다른 신고보다
  **먼저** 확인하고 조치한다.
- 조치 후 위 1절의 절차(강제 삭제 → 원본 격리 → 신고)를 그대로 따른다.

## 3. 관련 시스템 참고

- 강제 조치 함수: `admin_force_delete_room`, `admin_force_end_random_session`
  (`supabase/migrations/20260810050000_create_admin_action_functions.sql`)
- 신고 처리 화면: `/admin/reports` (`app/admin/reports/`, `app/actions/admin.ts`)
- 감사 로그: `admin_audit_logs` 테이블 — 모든 강제 조치가 자동 기록됨
